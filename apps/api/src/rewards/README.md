# rewards

The earned, non-transferable reward ledger (TD-15), and the invitations that earn into it (#107, ADR-044).

- `invitations.ts`, `routes.ts`: an invitation is a code a person whose profile is complete gives a friend (`POST /invitations`, 409 `invitation_not_yet` before that), at most `matching_config invitations_open` open at once (409 `invitations_full`), single use, drawn by `randomInt` from Crockford's alphabet, stored as the SHA-256 of the normalised code alone and shown once. `GET /invitations` is the caller's own, `DELETE /invitations/{id}` withdraws an open one. The friend types it after the bank login, before their own profile first passes that test (`POST /invitations/redeem`): the caller is checked first, under the account row's lock (409 `invitation_not_for_you`), then the code, one answer for unknown, used and one's own (404 `invitation_unknown`); `invitation_tries_per_day` tries a Finnish day, counted by the route's limiter (429 `invitation_tries_exceeded`). No code reaches a log line, an error detail, an event or the export.
- The night's count (`countInvitations`, run by `jobs/invitation-count.ts`) counts an invitation the first night its redeemer is complete (`RewardsDeps.complete`, the jobs' reader, handed in: ADR-060 §7), and writes the inviter's units, as `matching_config invitation_reward` says that night (read with `InvitationReward`, failing loudly), with one notice (`recordInvitationNotices`, ADR-032), in one transaction, its inviters locked first.
- `ledger.ts`: a unit is a like or a fish (`reward`). Matching's `decide` uses one by itself when the day's likes or the window's fish are spent (`spendEarned`), leaves what one paid for out of its counts (`entriesPaidBy`), and gives it back when that decision changes the same day (`releaseEarned`). The SQL that touches `reward` is this slice's (`repo.ts`); matching reaches it through `index.ts`.
- Erasure and export (ADR-044 §10): `eraseInvitationsOf` and `exportInvitations`, called by `identity/erasure.ts`. The person's units go by the account; of the invitations they made the open ones go, and a redeemed one stays for its redeemer with `inviter_account_id` null, so the redeemer has still redeemed one, ever, and keeps `used` in their export; the night never counts it. The invitation they redeemed goes until it counts, and once counted stays for its inviter with `redeemed_by_account_id` null. A row that would name nobody goes (`invitation_named_check`).
- Tests: `routes.test.ts` (the routes, the limiter, the races on one code and on the cap), `erasure.test.ts`, `jobs/invitation-count.test.ts`, `matching/earned.test.ts` (`features/matching/earned.feature`).
