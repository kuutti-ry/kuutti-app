# identity

Bank-ID registration, identity standing, accounts, sessions, re-registration. TD-1, TD-7. The Telia dialect itself is `@kuutti-ry/tunnistus-oidc` (ADR-017); `oidc-broker.ts` is the adapter that keeps Kuutti's part of a login. Staff sessions (#49, ADR-006): the same bank login marked as a staff attempt resolves to an identity with a `moderator_roles` row and an eight-hour admin session (`admin-session.ts`), never to an account. Erasure and export (#51, ADR-007): `erasure.ts` runs the erasure table over what exists and builds the export; `account-routes.ts` serves both to the caller's own account. The invitations (#107, ADR-044 §10) are the rewards slice's half: the person's units and notices go, and the invitations they made while open; those somebody redeemed stay for their redeemers without the person (`madeInvitationsDeleted`, `madeInvitationsKept`); the one they joined with goes until it counts and then stays for its inviter without them (`usedInvitationsDeleted`, `usedInvitationsKept` in `ErasureSummary`); the export carries each side's own, never a code or the other person. The research consent (#46, #50) also writes and removes the `research_subject` row through the research slice's surface, in the consent's own transaction. Taking a break (#170, ADR-022): `pause.ts` pauses the caller's account with its state kept aside and ends its sessions; `login.ts` ends the break at the next bank login and answers `unpaused`. "Löysin hänet" (#83, ADR-040): `found-them.ts` takes a person's word that they found someone, with a reason from a closed list, once per account; it changes nothing else, adds one to the day's anonymous count by reason (`found_them_count`, which names nobody and outlives erasure), keeps only `found_them_answered` on the account, and sends `found_them` for those in the study. The optional e-mail (#148, #385, ADR-043): `email.ts` sets, changes and clears the caller's address (a different one is unconfirmed and its waiting code goes), sends a six-digit code to it through `Deps.mailer` (`lib/mail.ts`) inside the transaction that counts the send in `email_send` and stores the code's SHA-256 in `email_code`, and confirms the address with the code, within `matching_config`'s minutes, attempts and codes a day; `account-routes.ts` serves `GET`, `PUT` and `DELETE /account/email`, `POST /account/email/code` and `POST /account/email/confirm`. Neither the address nor the code reaches a log line or an event; erasure deletes both tables' rows and the export carries `emailConfirmedAt`. The specification is `features/identity/email-confirmation.feature`, run by `email-confirmation.test.ts`; `email.test.ts` keeps the address's own routes, export and erasure.
