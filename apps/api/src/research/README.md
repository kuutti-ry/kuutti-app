# research

Event registry emission, research_id mapping, exports. TD-5. #50 (ADR-011): `track(deps, accountId, name, props)` is the one door, validated against `RESEARCH_EVENTS` in `packages/schema` and written only while a `research_subject` row exists for the account (the research consent's lifetime; identity writes and removes it in the consent's transaction, erasure removes it). `events` is partitioned by month: `partitions.ts` creates the current and next month at boot and nightly and drops months past the 90-day retention. `export.ts` is what the account export shows: the enrolment alone since ADR-011 §10 (the events are the researchers' material, never the person's copy); the research_id never leaves this directory. `anonymity.ts` is the nightly census of ADR-011 §9: distinct pseudonyms per cell of pond, age band and snapshot, a warning with counts only when a cell is under `RESEARCH_K_MIN`. The research copy (#194, ADR-029) is the nightly job `research-export`, before the partitions job: each closed UTC day the table holds and the copy lacks becomes one Parquet file, `research/YYYY/MM/YYYY-MM-DD.parquet` in the media bucket, written once (`copy.ts`, the run and the check before the prune drops a month; `copy-file.ts`, the columns; `copy-store.ts`, the bucket, put-if-absent). `copy-census.ts` is the copy's census: a value is released only when the copy's files of the previous ninety days and the day carry it for k pseudonyms whose consent is live that night (one per person: a withdrawn pseudonym counts for nobody), generalised under k as §9 says, `*` for withheld. The copy is wired only where media has a bucket, never in a preview, and not in production until the maintainer has answered ADR-029's ninety days.
