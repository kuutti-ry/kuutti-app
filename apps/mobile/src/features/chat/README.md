# chat

Conversations, presence, contacts shared in a conversation, auto-archive. TD-3.

- A photo in a message (#350): the composer's Add photo runs the media slice's chain before an upload (`pickPrepared`) and sends through its upload (`uploadPicture`) to `POST /conversations/{id}/photos`, with the field's words as the caption. `PhotoBubble.tsx` shows the thumb by `photoId/thumb`, the blurhash first, or "Photo removed"; a socket frame carries no URLs (rules/api.md), so the screen reads that one message again over HTTP, as it does for an expired URL, and `merged` never lets a socket's copy take a page's URLs. `ChatPhotoScreen.tsx` (`/chats/photo/<messageId>`) reads the message again for its `full`.
- `known.ts` drops a description key this build cannot say from a page, an answer or a frame (#296), so a newer API's label never fails a page.
- Contacts (#103): `YourContacts.tsx` is Settings' Your contacts screen (the settings slice wraps it in its page), a card per kind checked on the phone with `normaliseContact` before the API's own check. `ContactShare.tsx` is the conversation's share dialog, opened from Share contact in the header while one is kept and the conversation has not ended; `SharedContacts.tsx` shows what the other person shares under the header, as selectable text. The `contacts` frame carries no value: the store counts it per conversation, and the screen reads the conversation's contacts alone (`GET /conversations/{id}/contacts`, which signs nothing) on each and after every resume (the store's `opened`), one read at a time with one more after it for the frames that came meanwhile, merged into the detail shown; each read of the detail or of its contacts is numbered, so an earlier one never replaces a later one; a `conversation` frame that closes it shows nothing shared, since no contacts frame follows a close. A value is shown, never put in a path, a pressable's label, a test id or a log.
- Report, block or end (#351): the conversation's header has the safety slice's `ConversationActions` ("More") beside Share contact; End conversation calls `unmatchConversation`. After any of them the screen leaves the list a word (`notice.ts`) and goes back to it (`router.dismissTo("/chats")`), and the list says it once, aloud on iOS too. An ended conversation names nobody: "Conversation ended" in the header and its row, "The other person" before their messages, the ending in words where the composer was, and More with Report alone while the detail says `reportable`. A close the socket brings reads the detail again, so the name goes at once.
