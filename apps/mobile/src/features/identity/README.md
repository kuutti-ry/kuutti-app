# identity

Bank-ID registration, identity standing, accounts, sessions, re-registration. TD-1, TD-7. Taking a break (#170, ADR-022): `BreakScreen` says what happens and `pauseAccount` on the session provider does it; the sign-in screen says the account is on a break from the provider's notice, and the home screen welcomes an `unpaused` login back once. Your account's actions (`AccountActions`) open "I found someone" (#83, ADR-040), the settings slice's `FoundThemScreen`, by its route: telling Kuutti changes nothing, so this slice holds none of it.

The optional e-mail (#148), a way to stay in touch, confirmed by a code (#385, ADR-043): `EmailCard` holds the address with what the API last answered of it (confirmed, and until when a code waits), on its own Settings screen and as the last of the later screens (`EmailScreen`, which keeps the code's field above the keyboard as a settings screen does). Whether a code waits is the API's last answer, never the phone's clock: a code that runs out while the card is open keeps its field until Confirm's answer says it expired. The API's save sends nothing, so a failed send never fails a save: after a save that leaves the address unconfirmed with no code waiting, the card asks for one code by itself and says "Saved." and then what the send said, until when the code works or why it did not go. Every answer is a fresh notice in an assertive live region and, on iOS, said aloud, so a second code sent within the minute is said again. The six digits are typed on the card. The refusals of the code routes the card has words for (a wrong, spent, expired or missing code, the day's limit, no mail) say them, and any other says the code failed; the two that mean the address changed on another phone, `email_confirmed` and `email_none`, read it again and show what the API holds. An answer takes the field along unless the person has typed in it. `email-client` is the routes, through the typed client.
