# Security checklist

OWASP Top 10 (2025) mapped to this codebase. A diff that touches identity, auth, uploads, signed URLs, research events, or infrastructure is checked against every line here before it opens as a pull request. The `security-reviewer` agent in `.claude/agents/` runs this list; humans use it the same way.

The four surfaces that matter most, in order: the OIDC exchange with Telia, the hetu HMAC, session token issuance and validation, signed URL issuance for media. Everything else is CRUD with rate limits.

## Broken access control

- [ ] Every query that touches user data is scoped by the session's `account_id` inside the query, never by a check after the fetch.
- [x] Admin routes check role (moderator / admin / researcher) server-side, and the admin allowlist is by `hetu_hmac`. (#49: `requireAdmin` in `apps/api/src/lib/admin-middleware.ts` re-reads `moderator_roles` on every request; the row is keyed by the identity the `hetu_hmac` resolves to.)
- [x] No endpoint returns another user's data beyond what a profile card shows; no bulk export endpoint exists. (#52: another account's photo is issued a URL only against a `card_shown` row the card route writes for the viewer, one photo at a time and counted against the day's budget in the same statement, `apps/api/src/media/repo.ts`; `/account/export` is one person's own data, #51, as one zip with the photos inside, at most `matching_config exports_per_day` per Finnish day counted by `recordExport` in `apps/api/src/identity/repo.ts`, #237. The card: `buildCard` in `apps/api/src/profile/card.ts` serves another account's card only when the subject is `active` and complete, writes the shown records and counts the card in `recordCardServed`, and no route takes a subject id in M3, ADR-009 §6.)
- [ ] Hard filters are enforced in the round builder query, in both directions.

## Security misconfiguration

- [x] CORS: product API routes refuse browser origins; only the admin SPA, the waitlist site, and a pull-request preview's own web origin are allowlisted. (#52: `corsAllowlist` answers only the configured origins and production refuses http ones, `apps/api/src/lib/config.ts`; `app.test.ts` asks every route with an unknown browser origin, direct and preflight, and finds no Access-Control-Allow-Origin. #313, ADR-025 §10: staging's allowlist is exactly the panel's origin, `https://admin.staging.kuutti.app`, in `/kuutti/staging/cors-allowed-origins` from `infra/envs/staging`; the panel's previews under `/pr-<n>/` share that origin and need no entry of their own, and `build.yml` asks the API's CORS for that origin after each deploy of the panel.)
- [ ] No debug or introspection routes outside `NODE_ENV=development`.
- [ ] Deployed configuration comes only from SSM Parameter Store via the instance role; `.env` is local-only.
- [ ] CloudFront is the only public entry; nothing listens on plain HTTP. (ADR-005: the distribution fronts the API once `media_enabled` is set; the box still admits 443 from anywhere because Dokploy and the previews are served there directly, and 80 for the ACME challenge. `cloudfront_only_ingress` is the switch; the follow-up that lets it flip is in ADR-005.)
- [x] The panel's host serves from a private bucket that only its distribution reads, and every answer carries the panel's headers (#313, ADR-025, `infra/modules/admin`): origin access control signs every request, public access is blocked and the bucket owner enforced; the response-headers policy sends a CSP of `default-src 'none'` with `script-src` and `style-src 'self'`, the API's origin alone in `connect-src` and with `'self'` in `img-src`, and `worker-src`, `base-uri`, `form-action` and `frame-ancestors 'none'`, with HSTS (preload), `nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, a closed `Permissions-Policy`, COOP and CORP `same-origin` and `X-Robots-Tag: noindex, nofollow`, and `build.yml` reads them back after each deploy of the panel. The root is written by the `staging` environment's role; the plan role may put and delete `pr-*` objects and nothing else (`admin-previews`, `infra/bootstrap`), so a pull request can replace another's panel preview, never the root. A preview runs on the panel's origin and can read a staging staff session in the tab it is opened in: the trust is write access (ADR-004 §3), and staging holds invented people only (ADR-018).

## Supply chain

- [ ] `pnpm-lock.yaml` committed and installs use the frozen lockfile.
- [ ] `pnpm audit` blocks on high and critical.
- [ ] A new dependency with a `postinstall` script is called out in the PR description.
- [ ] Every dependency's licence is in `scripts/license-policy.json` or a named exception there (`pnpm check:licenses`); dependency review is green on the pull request.
- [ ] Images deployed by hand are verified first, against the workflow and the ref and not only the repository: `gh attestation verify oci://ghcr.io/kuutti-ry/kuutti-api:<ref> --repo kuutti-ry/kuutti-app --signer-workflow kuutti-ry/kuutti-app/.github/workflows/build.yml --source-ref refs/heads/main` (`refs/tags/vX.Y.Z` for a release). An image built before the organisation was renamed on 2026-10-03 is refused by this command: `infra/README.md`, "Build provenance", says how it is verified.
- [ ] GitHub Actions are pinned to commit SHAs (repo settings enforce it) and run with `contents: read` unless a step needs more.

## Cryptographic failures

- [ ] HMAC-SHA256 with the permanent SSM key is used for the hetu and for nothing else.
- [ ] Session tokens are random 256-bit values, stored hashed, compared in constant time.
- [ ] The hetu HMAC key and the Telia signing key are never in the database, the repo, logs, or the Dokploy control plane.
- [ ] TLS terminates at CloudFront; internal hops stay inside the VPC. (ADR-005: viewer TLS at CloudFront after the cutover; the hop to the box is HTTPS over the public address to `origin.api.<env>`, not inside the VPC, until the ingress switch above flips.)

## Injection

- [ ] Drizzle query builder only. Any raw `sql` template carries a reviewer comment explaining why.
- [ ] All input passes through a zod schema from `packages/schema` at the route boundary, including query strings, headers used for logic, and WebSocket messages.
- [x] Uploaded images are re-encoded by sharp with `limitInputPixels`; the original bytes are never stored or served. (#48: `apps/api/src/media/pipeline.ts`; the pixel cap is applied to the file header before the decoder, the route tests read the stored bytes back.)
- [x] The translator (`pnpm i18n:translate`) sends only message text (and approved translations as examples), the glossary and the tone guide to the Claude API; its output is validated and stays machine text until a native review (#55).

## Insecure design

- [ ] The change cites the TD entry or ADR it follows, or proposes a new ADR in `docs/adr/`.
- [ ] It does not add a compatibility score, desirability signal, infinite feed, real-time engagement push, or purchasable visibility (see the Product constraints section of `CLAUDE.md`).
- [ ] It does not widen what is stored about identity: no hetu, no legal sex, no full date of birth, no name.

## Authentication failures

- [ ] OIDC callback verifies `state`, `nonce`, the ID token signature against the issuer JWKS, `iss`, `aud`, `exp`, and the `acr` expected for FTN.
- [ ] Telia broker keys are fetched from discovery and rotate on their schedule; nothing is pinned.
- [ ] The app never holds a client secret; the exchange is backend-driven and the app receives a one-time code by deep link.
- [x] Sessions expire; a device change re-authenticates through the bank; admin sessions are 8 hours with no refresh token. (#35 for the product sessions; #49: `admin_session`, `ADMIN_SESSION_TTL_MS`, no refresh route, tested.)
- [ ] Re-registration honours identity standing: banned and suspended are refused, cooldown is enforced, nothing is restored.
- [x] A sanction ends what it says at once and leaves nothing to come back (#307, ADR-024): a suspension or a ban revokes every product session of the account and every panel session of the identity in the transaction that sets it; `insertSession` takes the account row's share lock and asks for the guard's live states and an `ok` standing, so a login racing a sanction never leaves a session that a lift would revive; a sanctioned or paused owner's photos are refused to others in `findVisiblePhoto`; a ban, its lift and its review are behind an admin-only guard on paths of their own; staff's note reaches no log line, error detail, event or export.

## Software and data integrity failures

- [x] EAS updates are not code-signed for now (ADR-004: Expo sells signing with its paid plans only), so the publish authority is `EXPO_TOKEN`, and any copy of it can publish to `production`: it exists only in the GitHub environments `staging`, `prod`, `preview` and `preview-cleanup` (the names of their secrets read through the API, 2026-09-28; none at repository or organisation level); `prod` keeps its required reviewer, `staging` admits only `main`, and `preview` loses its reviewer by the decision of 2026-10-08 (the maintainer from 2026-09-25, the day the `contributors` team got write, until the flip; ADR-004 §3): a pull request from anyone with write then deploys its preview without a click, so write access is the trust boundary of the update path, granted by name; no step that runs a pull request's bundler holds the token; no workflow edits a channel. Signing returns, or the reviewer goes back on, before a production build reaches people outside the team (ADR-004 §3 and §4, `docs/runbooks/custody.md`).
- [x] The `preview` environment has no required reviewer (ADR-004 §3, decided 2026-10-08): flipped on 2026-10-08 on the maintainer's instruction with the first command of `infra/README.md` Previews, Trust, and read back the same minute (`gh api repos/kuutti-ry/kuutti-app/environments/preview --jq .protection_rules`: `[]`). From 2026-09-25 until then the maintainer was the reviewer.
- [x] The environment `preview-cleanup`, which has no reviewer by design (ADR-012 §2), admits only `main` (ADR-012 §9): set by the maintainer on 2026-09-28 and read back the same hour (`gh api repos/kuutti-ry/kuutti-app/environments/preview-cleanup/deployment-branch-policies`: one policy, the branch `main`); a sweep from `main` passed the environment after it. From 2026-09-27 until then it had no policy, and a workflow on any branch that named it would have been handed `EXPO_TOKEN` and `DOKPLOY_TOKEN` without a review.
- [ ] `runtimeVersion` uses the fingerprint policy (compatibility between update and binary, not a protection).
- [ ] Migrations are generated by drizzle-kit, reviewed as SQL, and applied by the entrypoint under an advisory lock.
- [ ] Container images are built for arm64 in CI from a pinned base image, not on the box.

## Logging and monitoring failures

- [ ] Structured logs carry `account_id` and request id, never hetu, message text, email, `seeks`, or a client address.
- [x] The tunables change only by an admin, as a new version with a reason and the admin's identity, written to the audit table before the row (`config.change`), never a rewrite of an earlier version; a value keeps the shape its key's first version declared, a count its wholeness, sign and int4 range, so no reader is handed a value it does not parse or bind (#304, #305: `apps/api/src/safety/config.ts`, admin-only guard in `config-routes.ts`).
- [x] A person's page in the panel (#306) is reached by account id only (no search route exists), writes `account.view` before anything about the person is read, shows the profile through the card's own presenter, never the hash, the broker's ids, the research id or the e-mail, and an erased account's deletion date only (`apps/api/src/safety/account-routes.ts`, `accounts.ts`).
- [x] The audit log is read by admins only, fifty rows a page by a keyset cursor and never all at once: no route answers more than one page of audit rows and none exports them, and a read narrowed to one subject is itself an `audit.read` row about that subject (#309, `apps/api/src/safety/audit-routes.ts`, held by the route-table test in `app.test.ts`); the staff list only reads `moderator_roles`, and no route grants or revokes a role, which stays the maintainer's CLI (#310, ADR-006 §5, `staff-routes.ts`).
- [x] Moderator actions, disclosure requests, and photo views by staff write to the immutable audit table. (#49: `audit_log`, append-only by the trigger of migration 0006, written before the view or the change; the table and the trigger function are owned by `kuutti_audit` after `infra/scripts/db-audit-owner.sh`, so the application role can neither rewrite rows nor disable the trigger, and the API warns at every boot until that has run; disclosure requests join in M4.)
- [x] A test asserts that known PII patterns do not appear in log output. (#11: `apps/api/src/test/pii-in-logs.test.ts` sends a hetu, an e-mail address, message text and a session token through every route the router registers, in the path, the query, the headers and the body, and fails on any log line that carries one; a second case proves it would catch a route that logs its request body. #41, ADR-026 §7: an IPv4 and an IPv6 client address as well, in every trusted-proxy mode and through every refusal of the limiters and the sign-in doors.)
- [x] Signed URL issuance is logged per account (photo id, variant, time). (#48: a `photo_access` row and a log line per issuance, `apps/api/src/media/photos.ts`.)

## Mishandling of exceptional conditions

- [ ] No empty `catch` blocks; errors are logged with context and rethrown or mapped.
- [ ] Error responses are generic; detail goes to logs and Sentry.
- [x] Rate-limited and moderation-gated endpoints fail closed. (#52: a request without a trusted client address shares one bucket instead of bypassing the limit, `apps/api/src/lib/rate-limit.ts`; the address comes from the trusted proxy's own hop or header, never one the client wrote (audit F19), and the request id is the server's (F26); the exposure budget is counted under an advisory lock per account and variant, so a parallel burst cannot overshoot it, `apps/api/src/media/repo.ts`, ADR-008. #41, ADR-026: the window is counted by the client address until a guard admits the request, an IPv6 address by its /64 and an IPv4-mapped one as the IPv4 it maps, and an address that does not parse joins the shared bucket; a request a guard admits gives the address its count back in the same window and spends its person's budget instead, the account's or the staff identity's, one budget across the four guards and one count per request where two guards run; a token that opens no session stays on the address. The routes that end a session or the account (`ENDS_SESSION` in `apps/api/src/app.ts`: logout, logout-all, the panel's logout, delete, pause) are outside the person's budget, so a stolen session cannot spend it to keep the owner from them, and are never given back to the address, which bounds them. The two sign-in starts, `/auth/start` and `/admin/auth/start`, are the doors: they share a window per address, an IPv6 client by its /56, `SIGN_IN_RATE_LIMIT_PER_MINUTE` (10 in production), checked before the handler, so a refused start writes no `auth_request` row and has the broker sign nothing; the exchanges are no doors and stay under the address's limit. A start refused by the doors, by the address's limit or by the ceiling redirects to the app's link or the panel's page with `error=auth_rate_limited` and `Retry-After`, and leaves a `sign-in refused` warn line with `detail.limiter` `address` or `cap`, the signal the alarm counts, since the request line shows a 302, `apps/api/src/identity/routes.ts`. `auth_request` stops at 50,000 rows, a disk guard counted in the insert's own statement (concurrent starts can pass it by the connection pool's size at most); at the ceiling the expired rows go first, then the two oldest attempts without a code, deleted in the statement that inserts the new one, so no other start can take the room and an overshoot drains, and a flood shortens unanswered attempts rather than refusing everybody, each eviction a `sign-in refused` line with `detail.limiter: "evicted"`; an attempt ended while its callback waits on the bank answers `auth_state_mismatch` before the account is resolved, to the panel's page for staff; only a table whose every row holds a code refuses a start, the same way, so the ceiling still fails closed, `apps/api/src/identity/login.ts`. A key leaves memory within two windows of its last request, and no key reaches a log line, an error or an answer.)
- [x] Image processing returns 503 with `Retry-After` above the concurrency limit instead of queueing unbounded work. (#48: `p-limit` at the vCPU count, checked before the work is queued.)
