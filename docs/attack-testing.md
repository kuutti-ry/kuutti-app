# Attack testing: completion of #380

This is the coverage inventory and disposition record for [#380](https://github.com/kuutti-ry/kuutti-app/issues/380), following [ADR-021](adr/021-tests-at-every-level.md), [ADR-002](adr/002-gherkin-spec-vitest-runner.md) and [ADR-020](adr/020-end-to-end-flows-with-maestro.md).

The maintainer asked on 13 November 2026 for one final completion PR, with findings fixed in that PR and no new tracking issues. This record replaces the original issue's separate-ticket step for this work. A retained limitation below is an explicit scope decision, not a promised future fix. New testing can still discover new bugs; completion does not claim exhaustive proof.

## The test convention

Attacks remain beside their slice as `*.attack.test.ts(x)`. Vitest and jest-expo bind the shared helper in `scripts/lib/attack.ts`. Setup and observation run outside the inversion; only a synchronous assertion of the forbidden outcome may be inverted. Controls run ordinarily. Unexpected exceptions, rejected asynchronous observations and fixtures that never reach the boundary fail the suite. The Jest binding has its own real-matcher tests.

Seeded properties use the API's `property-attack.ts`: 100 examples per fixed seed, shrinking retained, and unexpected errors propagated even when a different shrunk counterexample is found. Rules-specification rows come directly from nine feature tables; malformed, duplicate or unbound rows fail instead of silently reducing the pile.

Maestro and Playwright use ordinary refusal assertions. They never invert an entire flow: a crash or an absent server must not be evidence that a rule held. The new signed-out-link flow first proves the same card, photos and conversations load with a session, performs and verifies logout, then proves those links cannot restore the data.

## Additional defects found while completing the piles

The mobile photo hook now discards an old signed-URL answer or refusal after a photo change/unmount and clears the old image while the next one loads. Three paired attacks and an ordinary unmount regression protect this. This is component reuse correctness; the tests do not claim an observed cross-account disclosure.

The panel's repeated Show photo controls now describe the photo's state and date. Browser checks also caught narrow layouts overflowing at 320 CSS pixels with enlarged text; the shared buttons, confirmation spacing and affected cards/headings now wrap within the viewport, with a browser regression. Pending controls use solid disabled styling.

No schema, stored personal-data field, consent wording or product parameter is added. The nightly changes implement the already documented retry/retention rules. A hung operation still holds the awaited nightly chain (4-07); a timeout that cannot cancel writes would create a different correctness problem.

## Why the ordinary tests missed these cases

The missing cases were mostly sequence and boundary tests: stale callbacks arriving after navigation, writes whose result arrives after dismissal, a reload racing an earlier reload, an image URL existing before its image loads, a page beyond a fixed retry batch, calendar retention crossing a leap year, or an argument/parser spelling outside the happy path. Each fixed case now has a direct regression or a paired control through the same boundary. Controls prevent a broken fixture from being mistaken for a successful refusal.

Temporary guard removal was used on the new piles and fixes. Examples include restoring all six old nightly implementations (six named violations), bypassing contract validators (all 27 attacks detect it), weakening the property guards (all 20 detect it), substituting controls for all 51 rules/ownership attempts, restoring the old runtime/checker guards, and the CLI, panel and mobile stale-photo mutations. All production sources were restored before the final green run. These are local mutation probes, not a claim that every possible mutation is killed.

Screen-reader walks remain a separate human check: automated accessibility assertions and browser captures are not VoiceOver or TalkBack walks. The completion PR and its commit name the changed screens as unwalked.
