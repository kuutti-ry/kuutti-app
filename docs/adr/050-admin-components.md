# ADR-050: The moderation panel's components: shadcn/ui on Tailwind, inside the panel's CSP

- Status: proposed (built as written here; it reverses #302's component decision at the maintainer's word of 2026-10-24; accepting it, and the points under "Open, the maintainer's", are his), amended by ADR-052 on 2026-10-24 (§4 and §6: Saiga in front of the system fonts, the build's `@font-face` for `/fonts/`)
- Date: 2026-10-24
- Follows: TD-9 (the app's design tokens and React Native Reusables, shadcn/ui's port to React Native), TD-2 (the stack, free tiers), ADR-025 §3 (the panel's content security policy), ADR-021 (tests at every level), CLAUDE.md (Accessibility; a new dependency: maintained, pinned, its licence in the policy), rules/admin.md (the component line of #302, which this replaces), the maintainer's request of 2026-10-24 ("an adequate UI for the admin panel, it looks like from the 90s, use some default best-practice UI library"); issues #302, #106

## Context

#302 settled the panel's components as plain React and one hand-written stylesheet (`src/styles.css`, 299 lines): no Refine, no shadcn ("the panel has no Tailwind"), no table library. It works and it is accessible, and it looks, in the maintainer's words, like the 1990s. He asked for a mainstream UI library.

The panel's host fixes what a library may do (ADR-025 §3). `style-src 'self'` has no nonce, since a static site on S3 cannot mint one per response, so a `<style>` element written at run time is refused and the browser reports a violation each time; a style set through the CSSOM, as React's `style` prop does, is allowed. `default-src 'none'` with no `font-src` fetches no font. `img-src` takes the host and the API's origin, never a `data:` URL.

What was checked, on the versions current on 2026-10-24, by reading what each ships:

- **Radix** (`radix-ui` 1.8.1): its Dialog, Select and the other overlays lock the page's scroll through `react-remove-scroll` 2.7.2, whose `react-style-singleton` writes a `<style>` element when an overlay opens. **Radix Themes** (3.3.0) is one static stylesheet over the same primitives, and has had no release since 2026-01-31.
- **React Aria Components** (1.22.1, Adobe): `usePress` prepends a `<style>` element to the page's head on the first pressable of every page in a production build, and `usePreventScroll` another for each modal on iOS.
- **Mantine** (9.7.3): its component styles are static files, but `MantineProvider` writes the theme's variables and its global classes as `<style>` elements (both can be turned off, and the variables then written by hand), responsive style props write one too, and its Modal uses `react-remove-scroll`.
- **Base UI** (1.9.0, by the authors of Material UI, Radix and Floating UI): only its Select and ScrollArea render a `<style>` element, and its `CSPProvider` turns that off (`disableStyleElements`). Its Dialog writes none.
- **shadcn/ui** (its registry and CLI 4.22.1): components copied into the repository and styled with Tailwind's utilities, which Tailwind v4 (4.3.3) compiles at build into one static stylesheet. Its button, card, table, badge, input, textarea, native select, label and alert are plain elements; its interactive widgets come in a Radix and a Base UI flavour.

The phone app already follows shadcn's pattern: React Native Reusables (TD-9) with the same token names, `class-variance-authority`, `clsx`, `tailwind-merge` and Lucide.

## Decision

1. **shadcn/ui, its Vega style, on Tailwind v4,** in `apps/admin/src/components/ui/`, the clients' horizontal folder for components (rules/layout.md). The components are copied from the registry (`base-vega`) and adapted, as shadcn intends; not generated by the CLI: the panel imports by relative path with the extension, so there is no `components.json` and no `@/` alias. `src/lib/utils.ts` holds `cn()`, as in the app.
2. **No primitive library for now.** Every widget the panel has is the platform's: buttons, inputs, the native `<select>` (shadcn's NativeSelect), radio buttons, `<details>`, and the confirm step of `src/lib/dialog.tsx`, which keeps the focus inside, closes on Escape, gives the focus back and makes the page inert, with its tests; it is now drawn as shadcn's Dialog. When the panel needs a widget the platform does not have (a combobox, a menu, a popover, tabs), the Base UI flavour of shadcn's component comes in, with `CSPProvider disableStyleElements` around the app and the few rules it would have written moved into the stylesheet. Never the Radix flavour, whose overlays write a `<style>` element.
3. **What changes in shadcn's components:** every control and every link that stands alone is at least 44 px tall (CLAUDE.md), and a button's label may wrap on a phone; one focus ring for everything, a 3 px outline in `--ring`, instead of shadcn's ring at half opacity; a destructive button and badge are solid (`--destructive` with `--destructive-foreground`, a pair the tokens' test holds), not tinted; the Alert is a paragraph with `role="alert"` and a decorative icon; a Card's title is an `h3` under the screen's `h2`; a Table's caption, which names it, sits at the top.
4. **The tokens** are shadcn's names, in `src/tokens.css`, with the app's palette (`apps/mobile/src/theme/tokens.css`), the page and the card swapped so the cards stand on a tinted page. Four whole sets, chosen by the system's settings: light, dark (`prefers-color-scheme`) and the high-contrast pair (`prefers-contrast: more`), a second set rather than a mode (CLAUDE.md). `src/tokens.test.ts` reads the file and holds every text pair to 4.5:1 (7:1 in the high-contrast sets), and the outline of a control and the focus ring to 3:1. Tailwind's `dark:` variant follows the same media query. System fonts only; ADR-052 puts Saiga in front of them.
5. **Meaning never by colour alone:** the current screen in the menu by weight and a bar (an underline in forced colours); Late by its word, its weight and a clock; a destructive action by its label and its place (the ban apart, at the end of the row); a chosen radio button by its dot.
6. **The CSP is held by tests and was checked by hand.** `vitest.setup.ts` fails any test of the panel during which a `<style>` element is written into the document. `preview-build.test.ts` holds the build to one stylesheet, Tailwind's, keeping its MIT line and naming no `@font-face` or `url(` but Saiga's faces under `/fonts/` (ADR-052), and lists the new packages in the licences file (#416). By hand, on 2026-10-24: the production build served with the CSP of ADR-025 §3 (the local API as the API's origin, the local S3 stand-in added to `img-src` for its photo URLs), signed in through the mock bank, every screen and the confirm steps opened, and the browser's console stayed empty (`docs/design/admin-ui-2026-10-24/`).
7. **The dependencies, pinned:** `tailwindcss` and `@tailwindcss/vite` 4.3.3 (build only), `class-variance-authority` 0.7.1, `clsx` 2.1.1 and `tailwind-merge` 3.7.0 (the app's versions), and `lucide-react` 1.52.0 (the app's Lucide release; its icons are placeholders until the designer's own). Their licences are MIT, Apache-2.0 and ISC, all in the policy, and none runs an install script. The app's NativeWind keeps Tailwind 3.4 at the root of the hoisted layout; the panel's Tailwind 4 is nested under it. Biome reads Tailwind's directives in the panel's stylesheet alone (`css.parser.tailwindDirectives`).

## Consequences

- rules/admin.md's component line names this record. A new screen is built from these components and tokens; a colour in a component is a token's name.
- The build grows by about 16 KB of script (gzipped: `tailwind-merge`, the icons) and the stylesheet from 3.7 KB to about 29 KB, uncompressed.
- Where a screen needed a wrapper for the look (a Card inside a list item), the markup changed; the five test assertions that named an old class now name an element, an attribute or a utility.

## Open, the maintainer's

- **Accepting it.**
- **A switch for dark and light in the panel.** It follows the system now, as the four sets do.
- **Tailwind's licence.** Its reset and utilities ship in the stylesheet, which keeps the one-line notice Tailwind writes at its top (`tailwindcss v4.3.3 | MIT License`); the licences file of #416 lists the bundled scripts only. Whether the notice is enough or Tailwind's licence text joins `licenses.txt` is his to say.

## Not done, and what would make it needed

- **Base UI and its CSPProvider:** when a widget needs it (point 2).
- **shadcn's Sidebar**, with its sheet on a phone: the menu is a column beside the screen and, on a phone, a row that scrolls with the current screen brought into view. A sheet is one more dialog; worth it when the menu outgrows the row.
- **A table library:** rules/admin.md's line stands; a list pages on the server.
- **The CLI's `components.json` and a path alias:** worth it once components are added often.
- **Screenshots in high contrast:** the browser used could not emulate `prefers-contrast`; the tokens' test holds the set.

## Alternatives considered

- **Radix Themes:** one stylesheet and a coherent look, but its overlays write a `<style>` element and it has not been released for nine months.
- **React Aria Components with Adobe's starter kit:** the strongest accessibility of the four, but every page would report a violation from `usePress`.
- **Mantine, its injection turned off:** possible, with the theme's variables kept by hand beside the library, and its Modal still writing a `<style>` element.
- **Base UI styled by hand:** the primitives without the look, which is what the maintainer asked for.
- **The hand-written stylesheet, polished:** what #302 chose and the maintainer has now turned down.
