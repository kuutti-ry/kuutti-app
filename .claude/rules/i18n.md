# Localisation rules

Consult `https://www.i18next.com/llms.txt`. `messages.yaml` is the source of truth; CI compiles per-locale JSON.

- Workflow: edit `messages.yaml`, run `pnpm i18n:build`, commit `src/generated/` with it (CI fails on drift, like the OpenAPI types). `packages/i18n/README.md` has the steps; `docs/i18n/tone.md` and `glossary.yaml` are the voice and the vocabulary.
- Keys are semantic (`profile.bio.required`), never the English text. Each key has `en`, a `description`, and `fi`; `sv` is filled by machine and released only once a native reviewer has cleared it (`RELEASED_LOCALES` in `src/locales.ts`: `en` and `fi` at launch). A production build and the production API serve only the released languages (`SERVED_LOCALES` in the app by update channel, `servedLocales(APP_ENV)` in the API); staging, previews and dev builds serve all three, so a reviewer reads Swedish there before it is released.
- `t()` is typed; a missing key, a missing ICU argument or a wrong argument type is a type error. Clients use `useT()` from `@kuutti/i18n/react`; the API uses `c.get("t")`. `pnpm lint` fails on a string literal in JSX text, as a JSX child, or in a prop that is read or heard (`accessibilityLabel`, `placeholder`, `title`, `closeLabel`, ...) in the clients' TSX. The API localises from this package using the account's stored locale (push, moderation notices, receipts, errors).
- Fallbacks: fi to en, sv to en. ICU plurals from day one. Dates and numbers through Intl, in Finland's conventions for every language: a date is d.M.yyyy in every language (`formatDate`, `formatDateTime`, `formatTime` in `src/format.ts`; the field sheet's Formats line, #150), never ISO, never month first; `intlLocale()` maps `en` to `en-FI` and `sv` to `sv-FI` (bare `en` is the United States' month-first order, bare `sv` is Sweden's ISO order) for times, `formatNumber`, `formatHeight` and ICU arguments through i18next-icu's `parseLngForICU`. `pnpm lint` refuses a date formatted in a client outside this package.
- Never inflect dynamic values. Proper nouns and user values appear only in nominative positions; case forms for ponds are stored per pond in the database. The pattern `in {pond}` is banned.
- `pnpm i18n:translate` fills missing fi and sv keys by machine with `machine: true`. Every fi and sv text carries either `machine:` or `reviewed:`, and CI fails on one with neither; `legal.*` is the exception and carries neither (its Finnish is the binding source, written by people and versioned by `consent_version`). Text an agent writes or edits in fi or sv is machine text and carries the flag; after changing a reviewed text or its English, run `pnpm i18n:review --reflag --locale <fi|sv> <key>`. `reviewed: { fi: "<hash>" }` is written only by `pnpm i18n:review --approve` or `--import` for a native reviewer, never by hand and never by an agent; the hash covers `en` and the text, so an edit to either fails CI until it is flagged again (#55). `docs/i18n/translation-review-guide.md` is the review.
- CI: missing fi fails, missing sv warns, a plural form the language needs or a select option of the English that is missing fails, `max_length` holds where it is set. `pnpm i18n:check --release` (a release tag, a production build) also fails on machine text in a released language and on draft legal text. `admin.*` is English only. The translator receives message text (approved translations of the same namespace as examples), the glossary and the tone guide, never anything from a database.
- Never machine-translate the privacy policy, consent texts, terms, or the police-traceability line. They are versioned by `consent_version` and the Finnish text is binding.
- Finnish runs about 30% longer than English; the `en-XA` pseudo-locale exists to catch overflow in dev builds.
