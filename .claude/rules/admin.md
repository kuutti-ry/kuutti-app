# Admin panel (Vite + React) rules

A static SPA built to S3 behind CloudFront (`infra/modules/admin`, ADR-025): `https://admin.staging.kuutti.app`, built from `main` against the staging API; `admin.kuutti.app` in production with #25. A pull request's preview is `/pr-<n>/` of the staging host, built with Vite's base `/pr-<n>/` and also against the staging API (a preview API has no bank); the router's basename is `import.meta.env.BASE_URL` without its trailing slash, so every in-app link goes through `Link`, `NavLink` or `navigate`, never a bare `href="/…"`. Staff sign in at the root and open the preview in the same tab, where the session is. It calls admin routes on the same Hono API, whose origin is the CSP's only `connect-src` and, with `'self'`, its `img-src`: no inline script or style, no third party, no asset inlined as a `data:` URL, and zod runs jitless.

- Components (#302, then ADR-050 at the maintainer's word of 2026-10-24, "use some default best-practice UI library"): React, `react-router`'s declarative routes (`BrowserRouter`, one path per screen), and shadcn/ui's components (Vega style) on Tailwind v4 in `src/components/ui/`, copied and adapted (44 px targets, one 3 px focus ring, solid destructive colours), compiled into one static stylesheet so the CSP's `style-src 'self'` holds. Colours are the tokens of `src/tokens.css` (light, dark and the high-contrast pair, by the system's settings; `tokens.test.ts` holds them to WCAG), never a colour in a component. Nothing may write a `<style>` element at run time: `vitest.setup.ts` fails the test that does, so no Radix primitive (its overlays write one) and no runtime CSS-in-JS. A widget the platform lacks comes from shadcn's Base UI flavour with `CSPProvider disableStyleElements` (ADR-050 §2); until then the controls are the platform's and the confirm step is `src/lib/dialog.tsx`. No Refine, no table library until a table needs sorting in the browser; a list pages on the server. The screens and the menu are one table in `src/app.tsx`, each with the roles it is shown to; the API's guard is what refuses. The front page at `/` is the overview of what waits (#303); a new queue joins it in `GET /admin/overview` and the overview's table.
- A screen the role does not open answers at its path with its heading and "Your role does not allow this", and asks the API for nothing (`NotForRole`, #304); the API's guard is what refuses.
- A screen's heading is `ScreenTitle` (`src/lib/screen-title.tsx`): it names the page's title and takes the focus after the person's own move inside the panel (`NavigationFocus` around the routes), never on a load, a reload or the front page's redirect. A list a screen loads from one route goes through `useList` (`src/lib/use-list.ts`). A 403 is said once by the shell (`admin.refused`) and taken back when a request is honoured again, never as the screen's or a row's own failure; a 401 ends the session.
- The bank returns staff to the panel's root; the panel remembers the path before the login and puts it back before the router starts (`features/identity/return-path.ts`).

- Auth: Telia login on web, allowlist by `hetu_hmac` (the `identity.hetu_hmac` column of #34, so the allowlist and the roles need no schema change: a `moderator_roles(identity_id, role)` table keyed by the identity row), roles moderator / admin / researcher checked server-side. Sessions 8 hours, no refresh.
- Launch screens: report queue (report, frozen conversation snapshot, both profiles by pseudonymous id, reporter history), photo review queue, actions warn / shadow-ban / suspend / ban with an appeal note, auto-shadow-ban threshold editor, `matching_config` editor.
- Every moderator action writes the immutable audit log (who, what, when, why). Photo views go through short-TTL signed URLs and are logged.
- Never auto-delete a photo, never expose a bulk export, never show `hetu_hmac` or `research_id` in the UI.
- A person's page (`/accounts/:id`, #306) is reached by an account id only, never a search by name or anything else; opening it is an `account.view` audit row, a photo on it is fetched only on request (`photo.view`), and its profile is the card's own presenter (`fieldsOnCard`), so staff see what others see.
- The audit log is read a page of fifty at a time (`/audit`, `GET /admin/audit`, #309), by a keyset cursor, never an offset; no route answers more than one page of audit rows (`AUDIT_PAGE_SIZE`, held by the route-table test), and there is no export; a read narrowed to one subject writes `audit.read` about it, as opening the person's page writes `account.view`. The staff list (`/staff`, #310) only reads: a role is granted and revoked with the maintainer's CLI (ADR-006 §5), never by a route.
- The report queue (`/reports`, #311) and one report (`/reports/:id`, #312): the queue writes no audit row and shows neither the note nor the conversation; opening a report is `conversation.view` (or `report.view` for a card's), fetched once per visit, a photo of its copy is fetched only on request (`photo.view`, the full variant), and both people are linked to their pages. The report's page acts on the person with #308's own actions (`SanctionActions`) and closes the report naming the sanction; a dismissal states its effect in its own confirm step. A member of staff who is a party to a report never sees it, and its address answers as an unknown report.
- The automatic shadow bans (`/automatic-bans`, `GET /admin/sanctions/automatic`, #105, ADR-033): the rules' bans nobody has confirmed or reversed, oldest first, never the reader's own, each with its rule in counts and times and Late past `auto_shadow_ban_review_hours`; Confirm and Reverse are #308's review step with the outcome fixed by the button pressed, nothing preset. The front page counts them as their own queue, late by their own hours. An audit row with no actor is the automatic rules', said so in words.
- A decision with an effect on a person goes through a confirm step that says the effect in words, with a reason chosen on purpose (nothing preset) and a note: a dialog (`src/lib/dialog.tsx`, drawn as shadcn's) that keeps the focus inside, closes on Escape and gives the focus back. An action a role may not take is left out of the screen (`useStaffRole`, from the shell), and the API's guard is what refuses it (#308).
- End-to-end flows (`apps/admin/e2e`, `pnpm e2e:admin`, ADR-051): Playwright in Chromium against the production build under the host's headers read from `infra/modules/admin/main.tf`, the mock bank and an API on a database and a bucket of its own; a console error, a warning or a CSP violation fails a flow. A new screen or step that only a browser can show (a redirect, the CSP, the focus across a real page) gets a flow there; its branches stay Vitest tests.
- English only. The accessibility rules in `CLAUDE.md` apply: keyboard navigation, labels, contrast.
- Same zod contracts from `packages/schema`; no hand-rolled fetch types.
